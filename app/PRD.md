[PRD] 오늘의 배터리 (Today's Battery)
1) 목표와 성공조건
1.1 프로젝트 배경 및 목표
배경: 현대인은 학업, 업무, 인간관계로 인해 만성적인 피로와 번아웃을 겪지만, 심리 케어 앱이나 정밀 진단 도구를 사용할 시간적·심적 여유가 없습니다. 기존 AI 서비스들은 추가적인 학습과 텍스트 입력을 요구하여 오히려 사용자에게 추가 피로를 유발합니다.
핵심 목표: 로그인, 결제, DB 저장 없이 접속 후 3초 만에 체력 게이지 슬라이더 조작만으로 현재 상태를 입력하고, 1분 안에 실천 가능한 맞춤형 회복 경험과 위로를 제공받는 단일 기능 B2C 웹 애플리케이션을 구축합니다.
1.2 성공 조건 (Key Metrics)
완독 및 실천율: 랜딩 페이지에 진입한 사용자의 85% 이상이 배터리 게이지 조절 및 원인 선택 후 '처방 카드' 생성을 완료함.
초저지연 UI 반응성: 슬라이더 조작 시 고양이 캐릭터의 비주얼/모션 변환 프레임 드랍이 없으며, 처방받기 클릭 후 결과 카드 노출까지 P95 기준 2.5초 이내 완료.
오류 없는 사용자 경험: API 장애나 네트워크 불안정 상황에서도 Fallback 시스템을 통해 사용자에게 에러 화면을 노출하지 않고 100% 힐링 처방 카드를 보장함.
2) 사용자 스토리
2.1 타깃 페르소나
페르소나 A (24세, 취업준비생): continuous한 시험 공부로 뇌정지가 온 상태. 복잡한 분석 리포트보다 당장 1분 만에 머리를 식힐 수 있는 구체적인 행동 지침이 필요함.
페르소나 B (31세, 직장인): 잇따른 회의와 업무 스트레스로 방전된 상태. 앱 설치, 회원가입, 본인인증 없이 접속 즉시 위로받고 빠르게 창을 닫을 수 있는 초간단 서비스를 원함.
2.2 핵심 사용자 스토리 (User Stories)
US-01 (상태 표현): 사용자는 텍스트 입력 없이 체력 게이지 슬라이더를 오르내리는 직관적인 조작만으로 자신의 방전/충전 상태(0%~100%)를 정할 수 있어야 한다.
US-02 (비주얼 피드백): 사용자는 배터리 게이지를 조절할 때 게이지 수치(0~100%)에 실시간으로 매핑되는 고양이 캐릭터의 표정과 모션을 보며 직관적인 감정적 위안을 얻어야 한다.
US-03 (원인 선택): 사용자는 제공되는 7가지 원인 태그 중 하나를 클릭하여 피로의 주된 요인을 단일 선택할 수 있어야 한다.
US-04 (처방 수령): 사용자는 [1분 맞춤 처방받기] 버튼을 눌러 상태 진단, 1분 힐링 루틴, 고양이 응원 메시지, 추천 BGM, 10초 미션이 포함된 처방 카드를 수령해야 한다.
US-05 (재시도 및 피드백): 사용자는 처방 카드에 대한 피드백(도움이 됐어요/별로예요)을 누르거나, [다시하기] 버튼을 통해 즉시 입력값을 초기화하고 재시도할 수 있어야 한다.

4.1 전체 데이터 처리 파이프라인 (1 입력 ➔ 2 검증 ➔ 3 처리 ➔ 4 출력)
[1. 입력] 사용자의 슬라이더 조작(battery_level) 및 원인 칩 클릭(fatigue_reason)    ↓[2. 검증] fatigue_reason 선택 여부 확인 (미선택 시 예외 처리 발생)    ↓[3. 처리] LLM API 요청 전송 (GPT-4o-mini, JSON Format) 또는 Fallback 작동    ↓[4. 출력] JSON 데이터 파싱 후 처방 결과 카드 UI 렌더링 및 프로그레스 바 충전 애니메이션 실행

4.3 LLM 프롬프트 및 응답 데이터 구조
Model: GPT-4o-mini
Parameters: temperature: 0.7, response_format: { "type": "json_object" }
System Prompt:
당신은 지친 현대인을 위해 위트 있고 다정하게 마음을 케어해주는 AI 힐링 코치 '오늘의 배터리 고양이'입니다.사용자가 입력한 배터리 잔량(%)과 피로 원인을 바탕으로, 1분 안에 현 위치에서 실천 가능한 맞춤 처방전을 JSON 규격으로 작성하세요.[출력 작성 원칙]1. status_comment: 현재 배터리 상태에 대한 위트 있는 한 줄 비유 진단.2. healing_routines: 지금 자리에서 1분 안에 실천 가능한 구체적 액션 3가지 (스트레칭, 호흡, 시각/감각 환기 등).3. cheering_message: 다정하고 따뜻한 고양이 말투의 응원 메시지 (2~3문장).4. recommended_bgm: 기분 전환에 도움 되는 BGM 무드/장르 1개.5. micro_mission: 10초~1분 내 완수할 수 있는 초간단 미션 1개.6. expected_charge_percent: 입력된 배터리 수치보다 +10%p~+25%p 상승한 예상 도달치 정수 (최대 100 제한).
LLM 응답 JSON Schema:
{  "$schema": "http://json-schema.org/draft-07/schema#",  "type": "object",  "properties": {    "status_comment": { "type": "string" },    "healing_routines": {      "type": "array",      "items": { "type": "string" },      "minItems": 3,      "maxItems": 4    },    "cheering_message": { "type": "string" },    "recommended_bgm": { "type": "string" },    "micro_mission": { "type": "string" },    "expected_charge_percent": { "type": "integer", "minimum": 0, "maximum": 100 }  },  "required": [    "status_comment",    "healing_routines",    "cheering_message",    "recommended_bgm",    "micro_mission",    "expected_charge_percent"  ]}
5) 예외 처리 (Exception & Error Handling)
본 시스템은 로그인/DB가 없는 단일 기능 서비스이므로, 사용자가 겪을 수 있는 모든 예외 상황에 대해 완전하고 정밀한 Fallback 및 Visual Feedback 정책을 정의합니다.
5.1 예외 상황별 세부 처리 명세
번호	예외 상황	발생 조건	예외 처리 및 UI/UX Fallback 상세 정책
1	태그 미선택	피로 원인 태그를 선택하지 않고 [처방받기] 클릭 시	- API 요청을 즉시 사전 차단 (preventDefault).

- 화면을 피로 원인 선택 영역(Chips Container)으로 부드럽게 스크롤 이동.

- 태그 컨테이너 테두리에 Red 점멸 애니메이션 (keyframes 2회).

- 버튼 상단 또는 태그 영역 위에 "피로 원인을 하나 골라주세요!" 안내 Red 툴팁 노출.
2	중복 클릭	[처방받기] 버튼을 짧은 시간 내 연속 클릭 시	- 버튼 클릭 발생 즉시 disabled = true 처리 및 클릭 이벤트를 차단.

- 버튼 내 아이콘을 로딩 스피너로 변경하고 텍스트를 *"고양이가 처방전 굽는 중..."*으로 전환.

- 중복 API 호출 방지 (Debounce / Throttle 적용).
3	응답 지연	API 호출 후 3초가 경과했으나 응답을 받지 못한 경우	- 결과 영역의 스켈레톤 UI(Skeleton Screen) 카드를 계속 유지.
